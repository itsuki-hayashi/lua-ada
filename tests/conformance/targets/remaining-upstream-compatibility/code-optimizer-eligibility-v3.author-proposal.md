# Pending observable optimizer-structure eligibility

This proposes a bounded version3 eligibility shape for the eight exact
`code.lua` candidates independently assessed in Root's `862ff67` feature
decision. It changes no validator, policy, original ledger, accepted scope,
transform or adapted source. The JSON is an author proposal with no installed
disposition, independent reviewer or execution evidence. Its regression list
is explicitly planned and has not been implemented or run.

The proposed shape records `module_observable: true`. A public binary dump
makes compiler choices observable; that visibility does not promise the C
compiler's exact constant placement, opcode stream, MOVE numbering or SETLIST
count. `module_compatibility_obligation`, `public_api` and `mixed_obligation`
must still be false after independent source/retention review. A public API
operation or actual Lua semantic requirement cannot use this shape merely
because it occurs in a test about optimization.

Version1 keeps its strict historical false-visibility requirement. Version2
keeps its pure retained-assertion conjunct rule. Version3 would be available
only under explicit `TargetPolicy remaining-upstream-compatibility`, with an
allowlist of the eight pinned code.lua child IDs, full-file/span hashes and
structure kinds in this packet. No other source, new kind or wider span gains
eligibility. All prior protected partitions, previous passing evidence,
public/mixed obligations, T-guard checks and independent-review requirements
continue to reject ineligible records.

All **51 original lexical records** remain untouched. The proposed eight
derived private children contain eighteen original lexical anchors. Their
future reference/decomposition decisions require independent review of both
the exact private child and any implied retained semantic obligations. The
other **33 original records**, including the whole-file manual audit, remain
required and pending. The presence of an excluded child cannot complete an
enclosing parent or produce passing execution evidence.

The source-bound retention input is the newly installed
`code-public-semantics.author-witness.json` and its ordinary Lua fixture and
twenty-nine named AUnit cases. They cover exact scalar value, math.type and
one-result cardinality; immediate and hexadecimal boundaries; eight actual
callback arguments; fourteen actual absent-key writes; nested maker/middle/
leaf lifetime and dumps; zero, one-nil and multiple returns; register load/error
boundaries; and49/50/51 constructor/vararg controls. This packet records those
source identities without importing the component observations as final
source or matrix acceptance. Their author packet remains pending semantic
retention review and needs fresh context observations and named receipts.

Every original checkR byte remains protected: offset2079, length127, SHA-256
`324530f639ef49280bcc33a77b56351c3369cdfd13290c63934071985bb880dc`.
All original checkK/checkI/checkF/checkints execution assertions, function
construction, successful maximum-register load, oversized-load diagnostic,
binary boundaries and final completion remain. Some opcode-only closures
intentionally error or loop forever; this proposal does not invent an
obligation to execute them. Public library helpers used to reduce private
inspection data receive no blanket public-API exemption; their global runtime
obligations remain separately required.

The existing exact transform machinery would continue to permit only empty,
complete-comment or punctuation replacements over independently resolved
private spans. Semantic strengthening is a separately reviewed counterpart or
equivalent, never executable code smuggled into a private exclusion. No fake
listk/listcode facade, T=nil, broad flag, early return, changed checkR, swallowed
public assertion or removed load can qualify.

The required order is independent schema/decomposition review; implementation
with security regressions; independent current-source retention and exact
decisions; policy installation; exact transform approval; then disposable
generation and fresh whole-source/final-context observations. Root's existing
feature-only decision does not skip any of those gates.

Source checks recomputed all eight candidate hashes and the checkR hash,
enumerated the51 original records and29 actual registrations, and confirmed
that the current validator rejects all eight unsupported version3 shapes.
No eligibility or runtime passing result is claimed by these checks.
