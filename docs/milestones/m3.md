# M3: Complete Lua 5.5.1 Upstream Coverage

Accepted: 2026-11-06, Asia/Tokyo. Status: **in progress**.
The current delivery is **M3-01: contracts, inventory, and baseline harness**.
Later gates are planned; this foundation does not implement their runtime APIs.

## Goal and delivery policy

Cover the pinned Lua 5.5.1 language, runtime, libraries, CLI, and public C API/ABI
through the full upstream test inventory. Preserve reference commit
`7579fc9d7ed90240487251dfb69168f8e64e9294` and every reference/module pin.
M3 absorbs the remaining M2 runtime work and the former C/binary compatibility
milestone. Native upstream C fixture libraries are included. The eight ecosystem
module fixtures and LuaRocks remain later M4 work.

Each numbered gate is a separate implementation task and PR, on a
`codex/m3-XX-*` branch. Start from updated master after the preceding PR is
merged by the maintainer. Publish verified work and open the PR against master;
do not merge automatically. A completed foundation gate does not complete M3.

## Coverage contract

The 34 upstream Lua files comprise one aggregate orchestrator (`all.lua`),
30 scheduled primary files, two helpers (`tracegc.lua`, `bwcoercion.lua`), and
the standalone allocation-exhaustion script `heavy.lua`. The latter is not
invoked by all.lua; commented-out heavy functions are not active test coverage.

Every active assertion or guarded test block needs a stable coverage entry
containing source revision/span/hash, invariant, configuration, original C
result, disposition, matching Ada case, and review evidence. Completion permits:

- Unchanged execution against Lua Ada.
- A reviewed Ada equivalent for a check tied to C implementation internals.
- A reviewed native-platform equivalent when matching native C Lua demonstrates
  that the original assertion is unsupported on that platform.

No unclassified, deferred, or silently skipped item may remain at acceptance.
An Ada-only failure is an implementation defect, not a platform exception.
Generated inventory candidates must be reviewed; their existence does not prove
that every semantic invariant or dynamically generated assertion is covered.
The [machine-readable inventory](../../tests/conformance/README.md) owns source
anchors, hashes, completion state, and validator rules.

Run unchanged all.lua wherever its native C baseline supports the original
assumptions. Where platform equivalents are necessary, use a separately named
aggregate runner preserving ordering, dump/load checks, cleanup, and aggregate
invariants. Report equivalent coverage as such, never as a literal unchanged
all.lua pass. Never alter production APIs to fake Unix devices or C internals.

T absent causes api.lua, code.lua, and memerr.lua to return early and skips
blocks elsewhere. Those exits are not passes of their omitted assertions.
Real C clients and the test adapter must exercise actual Ada C exports. Do not
fabricate opcode lists, C layouts, memory counts, or successful T responses.

## Configuration and safety profiles

Keep the following semantic/ABI configurations isolated in separate build and
report directories. Results from one do not establish the other's ABI.

| Configuration         | Required properties                                                                                                               |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Default               | int64, binary64, ASCII, LUA_COMPAT_GLOBAL=1, default public ABI                                                                   |
| Upstream instrumented | Applicable ltests.h settings, including LUA_COMPAT_GLOBAL=0, compatibility math, LUA_RAND32, test extra space and semantic limits |

The instrumented C build uses the unchanged ltests.h/ltests.c machinery. That
header also selects a 23-byte auxiliary buffer, small internal tables/caches,
68,000 VM stack slots, and 180 nested C calls. Record measured values rather
than assuming default layouts or limits. Native C default limits are distinct.

Lua allocation refusal, language stack overflow, and invalid/oversized chunks
are catchable semantic Lua failures. Configured host safety quotas remain
execution aborts. Do not weaken the existing Ada quota/recovery regressions.

The final CLI and standard C-created states will use Lua-compatible execution
defaults; bounded Ada sessions retain their defaults. This is future runtime
work, not a behavior change in M3-01. Conformance launchers must propagate their
explicit test configuration to every subprocess launched by the CLI tests.

| Test operation | Wall timeout  | Lua allocation ceiling |
| -------------- | ------------- | ---------------------- |
| Primary file   | 900 seconds   | 2 GiB                  |
| Aggregate run  | 3,600 seconds | 2 GiB                  |
| heavy.lua      | 600 seconds   | 64 MiB                 |

The heavy ceiling deliberately induces catchable allocator refusal rather than
exhausting the host. Unexpected exhaustion in regular coverage, crashes,
timeouts, and unexplained safety aborts fail acceptance. Test ceilings must not
become hidden product defaults or be silently raised after a failure.

## Architecture and interface commitments

- Move execution to canonical Lua 5.5.1 instructions while retaining idiomatic
  Ada values, ownership, contracts, and explicit native continuations. Exact C
  optimizer instruction sequences may need reviewed equivalents.
- Separate a shared universe from per-coroutine stacks, frames, errors, hooks,
  suspension, and closing. Centralize writes before collector barriers.
- Audit input-sized persistent and temporary allocations, not only heap-object
  creation. Expose stable C strings, userdata, and an opaque state address with
  correctly placed extra space. Match concrete public C structs too.
- Add a reviewed foreign-API execution portal for synchronous C callbacks.
  Reentry shares the universe, roots, allocator, counters, and protected state;
  it never calls Sessions.Execute or restarts budgets. Ada/native library
  callbacks continue using explicit continuation requests.
- No foreign longjmp may cross active internal Ada frames. Return typed statuses
  through Ada before C transfers; handle nested guards, yields and panic at the
  appropriate C-owned boundary. Resume saved continuation functions under fresh
  guards, without restoring abandoned C stacks.
- Preserve existing Ada checking/session interfaces and add the planned
  Bounded/Lua_Compatible execution policy deliberately. Set_Limits selects
  bounded policy. No public AST/prototype handles are introduced.
- Inventory pinned 5.5.1 headers directly, including seeded lua_newstate and
  external-string callbacks. Plain C hosts must not manually initialize Ada.
- Use standard Ada libraries by default, with narrowly justified C ABI, varargs,
  stdio, lifecycle, and OS glue. C glue must not implement the interpreter.

These are accepted design requirements. M3-01 adds no public runtime API,
canonical execution, collector mode, C facade, or CLI compatibility default.

## Final verification and reporting

Retain the 480-case M2b regression baseline and add separately named/commented
AUnit cases for each new behavior and defect. Preserve strict flags and runtime
checks. Serialize local Alire builds and retain reference/module pins.

Run per-file and aggregate campaigns with source/executable hashes, raw streams,
seeds, subprocess outcomes, configurations, warnings, and coverage artifacts.
Use targeted deterministic differential records: whole all.lua output includes
timings, memory counts, paths and seeds, and the suite emits expected warnings.
Require the appropriate final marker and successful exit; unexplained skip
messages or missing expected-warning behavior are failures.

Final acceptance requires the 18 default OS/profile/static/shared jobs, six
instrumented validation jobs (static/shared on each OS), and Windows static-PIC
validation in both configurations. Retain frontend/opcode, layout, differential,
and ABI checks. Inspect every required final-revision job log.

Report **complete covered upstream behavior** only after all coverage entries
and jobs pass. Distinguish original execution from reviewed equivalents; do not
claim every unchanged C-internal assertion executed on Ada. The milestone stays
open while any required gate, case, platform, or review finding is unresolved.
